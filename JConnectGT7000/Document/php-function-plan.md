# แผนเพิ่มฟังก์ชัน PHP

งาน React และ agent ชุด Phase 1 ของ React พักไว้ เอกสารนี้คืองานบนแอป PHP ในโฟลเดอร์ `frontend` ทำตามลำดับเฟส เฟสถัดไปเริ่มเมื่อ checklist ของเฟสก่อนหน้าถูกติ๊กครบ

การเพิ่มตารางหรือคอลัมน์ต้องเป็น SQL ใน `Database/migrations/` แบบเพิ่มอย่างเดียว และรันทับฐานเวอร์ชันเดิมได้ โดย PHP เดิมที่ยังไม่ได้อัปเดตโค้ดต้องล็อกอินและใช้งานต่อได้

สิทธิ์ปัจจุบันอยู่ในตาราง `ia_permission` คอลัมน์ `data` เป็น JSON ต่อ `user_type` ตรวจด้วย `CheckPermission($module, $method)` ประเภท `admin` ผ่านทุกโมดูล อุปกรณ์เก็บสถานที่ใน `devices.location` เป็นข้อความ ยังไม่มีต้นไม้สถานที่

## Phase 1

### 1. Backup และ Restore Config

สำรองและกู้คืนค่าตั้งค่าของระบบ ไม่รวมข้อมูลเทเลเมทรี `device_data` และไม่รวมไฟล์ log

สิ่งที่อยู่ในไฟล์สำรอง:

- `ia_setting`, `ia_menu`, `ia_permission`
- `devices`, `device_templates`, `device_categories` รวม `config` และ `metrics`
- เลย์เอาต์แดชบอร์ดและวิดเจ็ต
- `notification_channels` และเทมเพลตรายงานกับตารางเวลา
- `lorawan_applications` และค่า calculation / control ที่เป็นคอนฟิก

ผู้ใช้และรหัสผ่านไม่ถูกใส่ในไฟล์เริ่มต้น มีตัวเลือกแยกให้ใส่ `ia_users` ได้ตอนส่งออก

ไฟล์เป็น JSON มีชื่อซอฟต์แวร์และเวลาที่ส่งออก กู้คืนในทรานแซกชันเดียว ถ้าแถวใดผิด ทั้งชุดถูกยกเลิก ของเดิมก่อนกู้คืนถูกเขียนทับเฉพาะตารางคอนฟิก แถว `device_data`, `event_logs`, `alarm_logs` ไม่ถูกลบ

เมนูอยู่ใต้ System Setting ผู้ใช้ Global ที่ผ่านสิทธิ์ `setting` เท่านั้นที่เห็น

### 2. Data retention policy

กำหนดจำนวนวันที่เก็บข้อมูลปฏิบัติการ แล้วลบของที่เก่ากว่านั้น

| ตาราง | ค่าเริ่มต้น |
|---|---|
| `device_data` | 90 วัน |
| `event_logs` | 180 วัน |
| `alarm_logs` และ `alarm_log_dispatch` | 365 วัน |
| `health_check_logs` | 30 วัน |
| `report_export_files` | 30 วัน |
| `ia_sessions` | 7 วัน |

แต่ละตารางเปิดหรือปิดการลบได้ และเปลี่ยนจำนวนวันได้ ค่าเก็บใน `ia_setting` งานลบรันจากคำสั่ง CLI ของ PHP และจาก cron วันละครั้ง ก่อนลบจริงต้องมีโหมดนับจำนวนแถวโดยไม่ลบ ตารางคอนฟิกในข้อ Backup ไม่ถูกลบด้วยนโยบายนี้

หน้าตั้งค่าอยู่ใต้ System Setting มีปุ่มทดลองนับและปุ่มรันทันที

## Phase 2

### 1. Site Management

ต้นไม้สถานที่แบบไม่ล็อกความลึก ชนิดโหนดมีห้าแบบตามลำดับนี้เท่านั้น

`Main` → `Region` → `Site` → `Building` → `Room`

ระดับกลางข้ามได้ เช่น `Main` → `Room` หรือ `Main` → `Site` → `Room` ลำดับย้อนกลับไม่ได้ `Room` เป็นใบไม่มีลูก `Main` เป็นราก หนึ่งระบบมีได้อย่างน้อยหนึ่งราก

ตัวอย่างที่ใช้ได้:

- Main → Room
- Main → Region → Site → Building → Room
- Main → Site → Room

ตัวอย่างที่ใช้ไม่ได้:

- Room แล้วมี Site เป็นลูก
- Building แล้วมี Region เป็นลูก
- ชนิดอื่นนอกจากห้าแบบนี้

แต่ละโหนดมีชื่อ ชนิด พ่อ ลำดับแสดง และพิกัดละติจูดลองจิจูดเมื่อเป็น `Site` พิกัดใช้ปักหมุดบนแผนที่

อุปกรณ์ผูกกับโหนดได้หนึ่งโหนด ช่อง `devices.location` เดิมยังอยู่ เพื่อไม่ให้โค้ดเดิมที่ยังไม่รู้จักโหนดพัง การแสดงผลใช้ชื่อโหนดก่อน แล้วจึงใช้ข้อความเดิม

### 2. สิทธิ์

มีสองชั้นพร้อมกัน

**Level 1 Global** คือสิทธิ์เดิมใน `ia_permission` และ `CheckPermission` ไม่เปลี่ยนความหมายของ `own_read`, `all_read` และเมธอดอื่นที่มีอยู่ ประเภท `admin` ยังผ่านทุกโมดูล

**Level 2 Regional** คือขอบเขตสถานที่ ผู้ใช้ถูกผูกกับโหนดได้หลายโหนด และเห็นโหนดนั้นรวมลูกทุกชั้น ผู้ใช้ Global ที่เป็น `admin` เห็นทุกโหนด ผู้ใช้ Regional เห็นเฉพาะกิ่งที่ได้รับ

การเห็นเมนูใช้ทั้งสองชั้น ถ้าเมนูนั้นไม่เปิดให้ Regional ผู้ใช้ Regional ไม่เห็นแม้จะอยู่ใต้โหนดที่ได้รับ

### 3. เมนู

| เมนู | Global | Regional | หมายเหตุ |
|---|---|---|---|
| Home | เห็น | เห็น | ข้อมูลถูกกรองตามโหนด |
| Dashboard | เห็น | เห็น | แดชบอร์ดของโหนดที่เข้าได้ |
| Site Management | เห็น | เห็น | Regional จัดการได้ในกิ่งของตน |
| Device Management | เห็น | ไม่เห็น | |
| Notification Channel | เห็น | ไม่เห็น | Global เป็นคนกำหนด channel แล้วมอบให้ Regional |
| Alarm Logs | เห็น | เห็น | Regional เห็น alarm ของอุปกรณ์ในกิ่งตน |
| Event Logs | เห็น | ไม่เห็น | |
| Report | เห็น | เห็น | รายงานถูกกรองตามโหนด |
| User Management | เห็น | ไม่เห็น | |
| API Management | เห็น | ไม่เห็น | รายละเอียดอยู่ Phase 3 เมนูยังไม่ทำงานในเฟสนี้ |
| System Setting | เห็น | ไม่เห็น | รวม Backup, Restore และ Retention |

เมนูเดิมที่ชื่อ Devices, Notification, Device Template, Settings ถูกจัดเข้าชื่อในตารางนี้ ไม่เพิ่มเมนูซ้ำ

Notification Channel: ผู้ใช้ Global สร้างและแก้ช่องทาง แล้วเลือกโหนดที่ Regional ใช้ช่องทางนั้นได้ ผู้ใช้ Regional ไม่เข้าหน้าจัดการช่องทาง แต่การแจ้งเตือนของไซต์ตนใช้ช่องทางที่ถูกมอบ

### 4. หน้า Home

เพิ่มสามส่วนบนหน้า Home เดิม

**Site Tree** แสดงชื่อโหนดตามสิทธิ์ คลิกโหนดชนิด `Site` แล้วเปิดหน้ารายละเอียดไซต์และแดชบอร์ดของไซต์นั้น โหนดชนิดอื่นขยายหรือยุบกิ่งได้

**Widget Map** ใช้แผนที่จากวิดเจ็ตแผนที่เดิม ปักหมุดเฉพาะ `Site` ที่มีพิกัด สีหมุดใช้ alarm ที่ยังไม่ปิดของอุปกรณ์ในไซต์นั้น สีที่รุนแรงกว่าชนะ

| สถานะในไซต์ | สีหมุด |
|---|---|
| ไม่มี alarm | เขียว |
| มี Info | น้ำเงิน |
| มี Warning | เหลือง |
| มี Critical | แดง |

**รายการเขตและ alarm** แสดง Region กับ Site และจำนวน alarm ตามกิ่งที่ผู้ใช้เข้าได้ ผู้ใช้ Regional ไม่เห็นไซต์นอกสิทธิ์ทั้งในต้นไม้ แผนที่ และรายการ
